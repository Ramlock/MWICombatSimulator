# Buffs and modifiers

Commit documented: `95db2f6`. Every modifier source reaches the engine through one of two channels: **permanent buffs** (merged by `typeHrid`, built once, restored by `clearBuffs`) or **temporary buffs** (keyed by `uniqueHrid`, with a duration). Equipment is a third channel (summed into `combatStats`).

## The permanent-buff channel

1. `Player.createFromDTO` builds `HouseRoom`, `LabyrinthUpgrade`, `GuildBuff` objects (only entries with level > 0) and an `Achievement` (src/combatsimulator/player.js:51-69). `worker.js` sets `player.zoneBuffs = zone?.buffs || labyrinth?.buffs || []` and `player.extraBuffs = extraBuffs` (`src/worker.js:141-142`).
2. At the first `CombatStartEvent` (time 0) `generatePermanentBuffs()` runs (src/combatsimulator/combatSimulator.js:337-339). It iterates house rooms, labyrinth upgrades, guild buffs, achievement buffs, zone buffs, extra buffs and calls `addPermanentBuff` for each (src/combatsimulator/combatUnit.js:450-484).
3. `addPermanentBuff` keeps one entry per `typeHrid`, summing `flatBoost` and `ratioBoost` across sources; it keeps the first source's `uniqueHrid` and `duration` (src/combatsimulator/combatUnit.js:435-448). It does not copy `startTime`, so these buffs never expire (`undefined + duration` is NaN in `removeExpiredBuffs`, src/combatsimulator/combatUnit.js:487-489).
4. `reset()` → `clearBuffs()` copies `permanentBuffs` into `combatBuffs` and recomputes stats (src/combatsimulator/combatUnit.js:497-500, 539-556). `PlayerRespawnEvent` also calls `clearBuffs` (src/combatsimulator/combatSimulator.js:357).
5. Stat code reads the merged entry by `typeHrid` (`getBuffBoost`, src/combatsimulator/combatUnit.js:523-537). Buff types the stat code reads: `<skill>_level` (7), `max_hitpoints`, `max_manapoints`, `fury_accuracy`, `fury_damage`, `accuracy`, `damage`, `evasion`, `damage_taken`, `physical_amplify`, `water_amplify`, `nature_amplify`, `fire_amplify`, `healing_amplify`, `attack_speed`, `armor`, `water_resistance`, `nature_resistance`, `fire_resistance`, `hp_regen`, `mp_regen`, `life_steal`, `physical_thorns`, `elemental_thorns`, `wisdom`, `critical_rate`, `critical_damage`, `cast_speed`, `combat_drop_rate`, `rare_find`, `combat_drop_quantity`, `threat`, `retaliation`, `tenacity` (src/combatsimulator/combatUnit.js:176-376). Formulas for each are in `engine.md`. Any other `typeHrid` is stored but changes nothing.

## House rooms: the full trace

1. Modal built per room from src/combatsimulator/data/houseRoomDetailMap.json: `initHouseRoomsModal` (`src/main.js:151-182`). `player.houseRooms = {}` then `player.houseRooms[room.hrid] = 0` for all 17 rooms (`src/main.js:155, 158`). Input is a number, `min 0`, `max 8` (`src/main.js:184-195`); on `input` it stores `parseInt(value)` (`src/main.js:169-173`). An empty field gives `NaN`.
2. The map lives on the shared `player` object and is saved/restored per player tab (`src/main.js:4456` save, `src/main.js:4357-4378` and `4569-4578` load) and in equipment sets and exports (`src/main.js:3975`, `4068-4084`, `4222`). On import, missing rooms are reset to 0 (`src/main.js:4368-4372`).
3. Start: `startSimulation` pushes `structuredClone(player)` into `playersToSim` (`src/main.js:3183-3188`); the clone still carries `houseRooms`. It is posted as `players` (`src/main.js:3272-3279`).
4. Worker: `Player.createFromDTO(structuredClone(playersData[i]))` (`src/worker.js:140`) → `Object.entries(dto.houseRooms)`, creating `new HouseRoom(hrid, level)` for level > 0 (src/combatsimulator/player.js:51-55).
5. `HouseRoom` reads `houseRoomDetailMap[hrid]`; for each entry of `actionBuffs` and `globalBuffs` it creates `new Buff(entry, level)` (src/combatsimulator/houseRoom.js:15-26). `Buff` sets `flatBoost = flat + (level-1)*flatBoostLevelBonus` (same for ratio) (src/combatsimulator/buff.js:7-8). For example the dojo's `attack_level` (flat 1, +1 per level) gives `+level` attack levels; its `attack_speed` is ratio `0.005*level`; global `wisdom` is flat `0.0005*level` and `rare_find` flat `0.002*level` per room.
6. Time 0: `generatePermanentBuffs` → `addPermanentBuff` for every buff (src/combatsimulator/combatUnit.js:451-455) → `permanentBuffs[typeHrid]`.
7. `reset()` → `clearBuffs()` → `combatBuffs` → `updateCombatDetails` uses the sums (level buffs, `attack_speed`, `cast_speed`, `hp_regen`, `mp_regen`, `wisdom`, `rare_find`).
8. **Reaches combat:** the nine level/regen/speed buffs above plus `wisdom` (experience gain, src/combatsimulator/simResult.js:154) and `rare_find` (stored as `combatRareFind`; read for drops at `src/main.js:2015` via `simResult.rareFindMultiplier`, src/combatsimulator/simResult.js:226). **Does not reach any stat:** `efficiency`, `action_speed`, `enhancing_success`. The code never reads `usableInActionTypeMap`, so every room's `actionBuffs` are applied in combat whether or not the data marks them usable in combat.
9. UNCLEAR: whether the room buffs reaching the engine as above reproduce the game's behaviour; the document records only what the code does.

## Notes on stacking

- Level buffs apply as `level + level*Σratio + Σflat`, ability/consumable buffs of one `typeHrid` add together unless they share a `uniqueHrid` (then the newest replaces the older) (src/combatsimulator/combatUnit.js:176-183, 395-408).
- The permanent entry for a `typeHrid` is a single merged buff; it counts alongside temporary buffs of the same type in `getBuffBoost`.
- Ratio-style stat buffs (`armor`, resistances, `evasion`) use `base * ratio` where `base` excludes other buff flats (additive, not compounding) (src/combatsimulator/combatUnit.js:295-331, 217-223).
